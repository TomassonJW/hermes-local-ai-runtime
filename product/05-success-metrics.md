# Success metrics

## North star

A new Hermes-built application adds a local AI capability through a stable contract without selecting, installing, tuning, loading, monitoring or licensing the underlying model itself.

## Phase success

Bootstrap: validation, autonomous comprehension, no private context.

CPU prototype: local general VLM plus P0 specialists fit VM; refusal before pressure; other services remain usable; lifecycle/cancellation observable; provenance/review state returned.

Useful tool: auxiliary vision and document/vector/audio routes measured; operation understandable without low-level tuning; install/rollback reproducible.

Shared runtime: two independent consumers, no model hardcoding, engine/model replacement without consumer change, regressions caught.

Public product: supported Linux install, honest support matrix, reproducible public synthetic evaluation, security/licence/API policy.

## Measurements

Hardware profile, cold/warm latency, throughput, peak/idle RSS, CPU/pressure, swap delta, load/unload, context/image/audio budgets, quality/failure classes, cancellation, cache, engine/model/preset revision and licence/hash.

## Vision replacement

Never use one global vision score. Evaluate OCR exactness, document fields, screenshot/UI QA, charts/diagrams, object detection, image similarity, multi-image reasoning, tiny details, hallucination/abstention and resource cost. A local route replaces cloud only for task families meeting thresholds.

## Initial operational candidates

No sustained swap growth; RSS at or below 10 GiB; one heavy/two light; queue at or below 8; explicit resource error; responsive status/cancel and representative Hermes surfaces.

## Anti-metrics

Downloaded-model count, advertised context, maximum CPU use, pretty chat demo, copied vendor benchmark, one successful request or token savings without quality/maintenance accounting.
