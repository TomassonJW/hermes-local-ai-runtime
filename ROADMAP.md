# Roadmap

The roadmap is outcome-based. Dates are not commitments until measured work exists.

## Phase 0 — Compiled bootstrap

Self-contained product constitution, architecture, API/schema candidates, resource profile, provenance, missions, gates, state, handoff, UI contract and validation. Exit: G-00.

## Phase 1 — Takeover and visible shell

Hermes owns the repo, performs read-only preflight, delivers UI-00 with simulated truth states, verifies desktop/mobile, and stops for Thomas. Exit: G-01 and UI-00.

## Phase 2 — Engine and resource foundation

Refresh live profile; compare llama.cpp/llama-swap, LocalAI and specialists; prove lifecycle, crash recovery and resource admission. Exit: G-02, G-03, G-04.

## Phase 3 — Capability gateway

Native capability/job API, OpenAI facade, auth scopes, registry, route policy, provenance, result cache and observability. Typed clients after contract stabilisation. Exit: G-05.

## Phase 4 — Vision and document stack

Hermes auxiliary vision, general VLM, OCR, document parser, structured extraction, object/image specialists, evaluation and fallback policy. Exit: G-06.

## Phase 5 — Retrieval stack

Embeddings, reranking, multilingual evaluation, cache/batching and SDK examples. Exit: G-07.

## Phase 6 — Audio stack

whisper.cpp, VAD/chunking, alternative ASR evaluation, batch then streaming contracts. Exit: G-08.

## Phase 7 — Packaging and internal adoption

Supported Linux packaging, services, model store, notices, live operations UI, Hermes skill/toolset and first two consumers. Exit: G-09 and G-10.

## Phase 8 — GPU and distributed workers

Hardware discovery; CUDA/ROCm/Vulkan evaluation at acquisition; local/remote GPU workers; larger text/coding/vision/audio/TTS/generation candidates. No GPU vendor is selected by this bootstrap.

## Phase 9 — Public release

A third party can install, operate, evaluate and remove the runtime safely. Exit: G-11.
